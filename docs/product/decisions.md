# Book Studio Core — Decisions (append-only, newest first)

Entries before 2026-10-11 are reconstructed from commits, `CHANGELOG.md`, `AGENTS.md` and `docs/` in this repo; each
cites its source.

## 2026-10-13 · Post-build corrections move inside the gate; drafts get a core command

- **Context**: in the private workspace, all four delivered Vietnamese editions differed from the EPUB that `finish`
  had certified. Per-book scripts had changed them afterwards: wording, contents pages, CSS, a cover mark. Roughly 35
  per-book scripts repeated four needs. Book work happens in Codex (299 sessions, against 5 in Claude Code), and there
  is no external audience yet.
- **Decision**: add `PROJECT/edits.json`, which declares hash-pinned `replace_text`, `replace_member` and `add_member`
  operations that `build` applies, so `finish` certifies the delivered book. Add `apply-drafts` for whole-chapter
  drafts through the unchanged packet contract. A cover mark is drawn outside the core (it needs an imaging library)
  and enters the book as a declared `add_member`, so the core stays standard-library only. The workspace scripts are
  frozen; no new features go there. A Claude Code port, an MCP Apps widget and plugin artwork are deferred.
- **Evidence**: `tests/test_edits.py` (BSC-EDIT-001…007), `tests/test_drafts.py` (BSC-DRAFT-001…004). On a private
  copy of a real book, 14 captured operations reproduced the delivered edition member for member, and the gate hash
  equalled `final.epub`.
- **Reversal**: delete `edits.json` from a project (its build returns to the plain core output). Removing the feature
  means reverting `epub/edits.py`, `translation/drafts.py` and their CLI wiring, then regenerating the plugin bundle.

## 2026-10-13 · Add a read-only local review page before any in-chat widget

- **Context**: people judge the sample and follow progress through JSON and terminal text. Agent hosts can render
  MCP Apps (`ui://`) widgets, but Codex Desktop support was unconfirmed when this was decided: it sat behind a
  feature flag, and nested calls did not render. A widget would also need an MCP server and a JS bridge dependency.
  Book text must never leave the machine.
- **Decision**: add `bookstudio review PROJECT`. It writes one self-contained, script-free HTML page to
  `reports/review.html` using only the standard library, and it works the same in Codex, Claude Code, or a plain
  terminal. Approving and revising stay CLI commands; the page prints the exact next command. Interface text is
  English, matching the CLI. A later in-chat widget can reuse this page.
- **Evidence**: `src/bookstudio/review.py`; `tests/test_review.py` (BSC-REVIEW-001…007); `logic/review-page.md`.
- **Reversal**: remove the `review` command, `review.py`, and its tests, then regenerate the plugin bundle; a new entry
  here.

## 2026-10-11 · Product docs live in `docs/product/` with REQ-IDs next to the tests

- **Context**: behaviour was described in engineering docs (`docs/*.md`) and tests, but there was no product-level
  goal, per-feature rule list, decision log or release record.
- **Decision**: keep a goal, UX and logic docs for three features (translation pipeline, guided intake and pilot,
  portable skill and plugin), this log and a release list in `docs/product/`. Every live rule carries a REQ-ID
  (`BSC-PIPE`, `BSC-PILOT`, `BSC-SKILL`) as a one-line comment next to its test. Comments go in `tests/` only, because
  any byte change under `src/bookstudio/` or `skills/book-translation/` drifts the generated plugin bundle.
  Engineering docs stay where they are and are linked, not copied.
- **Evidence**: this commit; `docs/product/logic/*.md`.
- **Reversal**: remove `docs/product/` and the `# BSC-…` comments; a new entry here.

## 2026-09-13 · Ship an installable Codex plugin that bundles its own engine

- **Context**: installing a Python CLI plus a separate skill was a barrier, and a global CLI could differ from the
  version the skill expects.
- **Decision**: add `plugins/book-studio` with the skill and a byte-identical copy of the engine, generated by
  `scripts/build_plugin.py`; CI fails on bundle drift. The standalone CLI and skill remain supported.
- **Evidence**: commit `e027d96`; `docs/codex-plugin.md`; `tests/test_plugin.py`; REQ BSC-SKILL-001…003.
- **Reversal**: remove the plugin folder, the marketplace file and the CI step; a new entry here.

## 2026-09-02 · Personal-use licence instead of MIT

- **Context**: the workflow processes copyrighted books; an MIT licence said nothing about what may be done with the
  generated books.
- **Decision**: replace MIT for current and future distributions with the source-available Book Studio Personal Use
  License 1.0; generated books stay private and non-commercial; commercial use needs written permission from both the
  software licensor and every rights holder.
- **Evidence**: commit `1671d21`; `CHANGELOG.md` (Unreleased); `LICENSE`;
  `skills/book-translation/references/personal-use-and-rights.md`.
- **Reversal**: a licence change is a new entry here; earlier MIT-licensed copies keep their licence.

## 2026-09-02 · PDFs enter through a fail-closed gateway, not OCR

- **Context**: readers also hold PDFs, but scans, sparse text and complex layouts cannot be converted reliably.
- **Decision**: add `pdf inspect` / `pdf prepare` using optional local Poppler tools; only sources with a sufficient
  text layer are prepared, into a semantic EPUB that must be reviewed (exit 2, `source_review_required`) before
  translation. No OCR and no new Python dependency.
- **Evidence**: commit `1671d21`; `docs/pdf-source-preparation.md`; `tests/test_pdf_source.py`.
- **Reversal**: remove the `pdf` commands; a new entry here.

## 2026-08-30 · A representative pilot must be accepted before the whole book

- **Context**: a whole-book run with the wrong tone, terminology or image policy wastes the run.
- **Decision**: guided `start` locks the reader's answers and proposes one representative chapter; full scope unlocks
  only after `pilot accept --confirm`, and later drift in the locked policy fails closed.
- **Evidence**: commit `6abd800`; `CHANGELOG.md` (0.1.0); `docs/guided-intake.md`; REQ BSC-PILOT-007…013.
- **Reversal**: a new entry here; direct `init` projects already run without a pilot.

## 2026-08-30 · Provider-neutral, standard-library-only engine that never calls a model

- **Context**: tying the engine to one AI provider or adding dependencies would widen the trust and supply-chain
  surface for a tool that handles private books.
- **Decision**: Python 3.11+ standard library only; the engine emits packets and accepts responses as local JSON; no
  bundled provider client; AI output is untrusted until validated; the public tree is guarded by an allowlist-first
  `public-audit`.
- **Evidence**: commit `6abd800`; `AGENTS.md`; `pyproject.toml` (`dependencies = []`); `docs/architecture.md`;
  REQ BSC-PIPE-005…012.
- **Reversal**: adding a dependency or adapter needs an explicit maintainer decision recorded here.
